# Blog structure template (MTE)

Every article (FR first) follows this shape. Length ~800–1400 words. Plain, expert, practical.

1. **H1** — the keyword phrased as a real question or task (e.g. "Programme d'automate perdu : comment le récupérer").
2. **Intro (2–3 sentences)** — name the problem the reader has (machine down, program lost, drive faulty). No fluff.
3. **The short answer** — 2–3 lines so a hurried reader gets the gist immediately.
4. **Body (H2/H3)** — the real explanation: concrete brands/models, steps, what to check, what it costs to consider. Only facts that match `features.yaml`.
5. **How MTE helps** — one short, honest paragraph tying it to the real service (PLC/HMI programming or repair). No invented numbers.
6. **Internal links** — the pillar/service page + one relevant `/outils` calculator + one related article.
7. **CTA** — WhatsApp + "devis gratuit", with the phone number.
8. **FAQ (2–4 Q&A)** — reuse real questions (feeds FAQ schema).

**E-E-A-T signals:** written as a working engineer; concrete tools (TIA Portal, Altivar codes…); Médéa/Algeria context; a real workshop + on-site service.

**Checks before human-review:**
- No fabricated feature, number, or testimonial.
- No cannibalisation of an existing page (see content-map.yaml).
- One clear primary keyword; secondary keywords used naturally.
- Links up to the pillar; links to at least one /outils tool.
